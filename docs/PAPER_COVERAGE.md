# Paper-to-code audit

Reference: [DeepSeek-R1, arXiv:2501.12948v1](https://arxiv.org/html/2501.12948v1), 22 January 2025.
Upstream snapshot: `5b6ff22` (full revision recorded in each run). This project originally supplied separate
SFT, GRPO, generation and cluster evaluation programs, rather than a complete reproduction of every paper experiment.

**This fork does not claim 100% reproduction of DeepSeek-R1.** It adds a runnable, inspectable reduced pipeline while
preserving the original cluster paths. Completing algorithms at small scale is different from reproducing training
data, model scale, benchmark results or emergent behavior. DeepSeek's unpublished data/preference models and full
training configuration cannot be reconstructed from this repository.

| Paper component | Implementation / evidence | Fidelity and limits |
|---|---|---|
| §2.2.1 GRPO | `local/training.py`: `group_advantages`, `grpo_loss`, `train_grpo`; original `grpo.py` retained | Group-normalized advantages, clipped old-policy ratio, frozen reference, k3 KL, per-response token mean. No critic. Uses sample std + 1e-4. |
| §2.2.2 accuracy and format rewards | `local/data.py`; original `rewards.py` retained | Local arithmetic, logic and bounded expression tests. Original math-verification and remote code backends retained. Local accuracy requires one answer tag. |
| §2.2.3 template | `local/data.py`: separate question, thought and final answer | Small grammar, not the paper's long natural-language problem distribution. |
| §2.2.4 R1-Zero | `base → r1_zero` | No cold-start SFT on this branch. Offline base is a synthetic language-model bootstrap, not a general pretrained LLM. Sparse rewards can yield no learning. No claimed “aha moment”. |
| §2.3.1 cold start | `base → cold_start` | Reference traces generated by a deterministic task generator, labelled synthetic; not DeepSeek-generated or human-curated long CoT. External JSONL supported. |
| §2.3.2 reasoning RL | `cold_start → reasoning_rl` | Accuracy, format, English consistency proxy. ASCII checks are deliberately limited to the synthetic English grammar. |
| §2.3.3 rejection sampling | `reasoning_rl → rejection_sampling` | Actual sampled successful traces only; saves all candidates and failures. Empty acceptance fails the pipeline. No oracle substitution. |
| §2.3.3 second SFT | `base + rejection mixture → mixed_sft` | Restarts from the original base; mixed reasoning/general data. Approximately 3:1 unique records when available. Uses fixed step budgets, not the paper's 800k samples / two epochs. |
| §2.3.4 all-scenario RL | `mixed_sft → reward_models → alignment_rl` | Two pairwise-trained preference models; helpfulness scores final answer, harmlessness full response. Synthetic preferences are not DeepSeek-V3 reward models or a validated safety measure. |
| §2.4 distillation | `student_base + rejection mixture → distillation` | Smaller independent dense model, SFT only. Uses the §2.3.3 corpus, as specified by the paper. HF adapter backend currently uses the same backbone for the student: it is adapter transfer, not compression. |
| §3 benchmark protocol | `local/evaluation.py`; original LightEval commands retained | Local pass@1, pass@k, majority, length, formatting, truncation and prompt-cluster SE. Sampling uses temperature 0.8, no top-k/top-p filtering; not the paper's 64 samples, temperature 0.6/top-p 0.95, 32,768-token limit. |
| §3.1 full R1 benchmarks | Original `scripts/run_benchmarks.py`, `utils/evaluation.py`, Slurm recipes | Not executed on M1. Includes academic, multilingual, coding and preference benchmarks beyond the local corpus. |
| §3.2 all six distilled model sizes | Original model recipes + local small student | Full 1.5B–70B matrix not executed. |
| §4.1 distillation versus direct RL | `distillation` versus `student_rl`, same student base | Functional comparison. Fixed step counts do not equalize compute or data exposure; no extrapolation to the paper's 32B conclusion. |
| §4.2 PRM / MCTS | Documented, not implemented as claimed successes | These are unsuccessful explorations, with insufficient recipe details for exact replication. Not required by the successful R1 algorithm. |
| Local extra ablations | `ablation_no_kl`, `ablation_no_language` | Same starting model, prompts and initial RNG seed as reasoning RL; policies naturally diverge after updates. These are local diagnostics. |

## Algorithm and engineering decisions

- Completion masks exclude prompts and right-padding, and include the first EOS token. SFT loss averages completion tokens.
- Each GRPO batch is a group of completions from one prompt. Old likelihoods are detached, the reference is frozen
  for the entire RL stage, and two policy updates reuse the same sampled group. All three likelihoods use the same
  temperature-adjusted distribution as sampling. Dropout is disabled during RL; gradients remain enabled.
- Inference uses a KV cache; differentiable scoring disables it. Float32 and eager attention avoid CUDA-only kernels.
- All local stage boundaries save checkpoints and SHA-256 receipts. Resume validates source, configuration, data
  and completed artifacts; a failed stage restarts from its parent. Mid-optimizer-step recovery is not implemented.
- Train/validation/test prompts are disjoint. Commutative arithmetic duplicates are excluded. General and safety
  test records hold out request IDs, not semantic templates. Test outcomes are never used for model selection.
- No generated arbitrary Python is executed. The local code verifier interprets a tightly bounded arithmetic AST.
  Existing external sandbox providers remain the path for real competitive programming evaluation.

## What full replication still requires

The DeepSeek-V3/R1 scale model family, original or comparably curated large training corpora, a general reward-model
training corpus, distributed accelerators, full benchmark datasets and their licensed executors, substantially longer
training and generation, and multi-seed statistical analysis at that scale. The M1 runs establish neither the original
scores nor equivalent general capabilities. See each checked-in run's raw outputs and `REPORT.md` for measured results.
